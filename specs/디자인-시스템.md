# 디자인 시스템

[HTML 갤러리](디자인-시스템.html)는 Cupertino 선택 이전의 시각 초안이다. 현재 구현 기준은 Flutter의 독립 카탈로그(`/catalog`)다. 카탈로그 예시는 디자인 검토용이며, 앱의 사용 시나리오를 확정하지 않는다.

## 목적과 상태

기능을 추가해도 같은 앱으로 보이도록 색상·서체·간격·컴포넌트·상태 표현의 공통 기준을 둔다.
제품 스펙과 별도로 관리하며, 특정 화면에만 적용되는 배치는 화면 설계에서 다룬다.

이 문서는 첫 초안이다. 아래의 시각 스타일과 수치는 Sam의 제안이며 Beck이 확정한 디자인이 아니다.
실제 컴포넌트를 한곳에서 비교하고 한국어 콘텐츠와 긴 문장으로 확인한 뒤 기준으로 확정한다.

## UI 기반 — 확정

Beck은 iOS와 Android 모두 Cupertino를 기본 UI로 사용하기로 선택했다.

1. 앱 루트는 `CupertinoApp.router`, 화면은 `CupertinoPageScaffold`, 내비게이션 바는 `CupertinoNavigationBar`를 사용한다.
2. `go_router`의 기본 `builder`가 Cupertino 경로를 생성하도록 한다. 전환 시간·곡선·애니메이션을 별도로 지정하지 않는다.
3. 버튼·입력·필터·대화상자·진행 표시는 Cupertino의 기본 위젯과 동작을 사용한다. Android용 Material 분기를 만들지 않는다.
4. 색상은 Cupertino의 동적 시스템 색상으로 정의하며, 기본 컨트롤의 스타일을 임의로 다시 그리지 않는다.
5. 콘텐츠 행·상태 배지·추천 카드 등 앱 전용 표현은 공통 컴포넌트로 유지한다.

현재 `go_router`가 사용하는 공식 `cupertino_ui` 패키지로 앱과 공통 위젯의 import를 통일한다. SDK의 이전 `flutter/cupertino.dart` 타입과 혼용하면 라우터의 앱 유형 감지가 실패할 수 있다.

## 시각 방향 초안

콘텐츠의 제목과 저장한 이유를 읽기 편하게 보여주는 차분한 개인 보관함을 지향한다.
콘텐츠 표지와 이미지가 다양해도 화면의 골격은 일정하게 유지한다.
`Surprise me`에는 일반 기록 기능보다 눈에 띄는 강조를 허용한다.

1. 밝은 중성 배경, 명확한 글자 대비, 하나의 주 강조색을 사용한다.
2. 기본 목록은 행으로 구성한다. 카드 표현은 추천 결과처럼 하나의 대상을 강조할 때 사용한다.
3. 콘텐츠 종류마다 별도의 색상·버튼·카드 스타일을 만들지 않는다. 종류는 텍스트와 아이콘으로 구분한다.
4. 발견한 출처와 실제 접근 링크를 구분하고, 접근 동작은 명시적인 문구로 표현한다.

## 공통 토큰 초안

색상 이름은 역할을 나타낸다. 화면에서는 색상 값 대신 해당 역할을 사용한다.
다크 테마에서도 같은 역할을 유지하되 값은 별도로 정의한다. 아래 색상은 Cupertino 테마와 현재 밝기에 따라 해석한다.

| 역할 | Cupertino 기준 | 용도 |
| --- | --- | --- |
| background | 기본 scaffoldBackgroundColor | 화면 배경 |
| surface | secondarySystemGroupedBackground | 카드 영역 |
| textPrimary | label | 제목·본문 |
| textSecondary | secondaryLabel | 출처·보조 설명 |
| outline | separator | 구분선 |
| accent | 기본 primaryColor | 주요 동작·선택 표시 |
| onAccent | primaryContrastingColor | 강조색 위의 글자 |
| accentSurface | primaryColor의 12% 불투명도 | 앱 전용 추천 카드·배지 |
| error | systemRed | 오류 설명 |

1. **간격:** 4·8·12·16·24·32. 화면 좌우 여백은 16, 섹션 사이는 24를 기본으로 한다.
2. **모서리:** 기본 컨트롤은 Cupertino의 기본값, 앱 전용 카드는 16. 상태 배지는 둥근 캡슐 형태로 통일한다.
3. **아이콘:** 기본 24. 같은 아이콘 계열을 사용한다.
4. **터치 영역:** 기본 컨트롤은 Cupertino의 기본 터치 영역을 사용한다.
5. **서체:** 기본 서체는 Cupertino 테마에 따른다. 글자 크기 확대 설정을 반영하며 고정 높이로 본문을 자르지 않는다.

| 텍스트 역할 | 크기 / 굵기 | 용도 |
| --- | --- | --- |
| screenTitle | 24 / 600 | 화면 제목 |
| sectionTitle | 18 / 600 | 섹션 제목 |
| itemTitle | 16 / 600 | 콘텐츠 제목 |
| body | 16 / 400 | 기록·추천 이유 |
| metadata | 14 / 400 | 종류·출처·시각 |
| action | 14 / 600 | 버튼·동작 |

본문 행간은 글자 크기의 1.5배를 시작점으로 삼아 한국어 실물에서 조정한다.

## 공통 컴포넌트

| 컴포넌트 | 표현과 동작 |
| --- | --- |
| 주요 버튼 | `CupertinoButton.filled`. 한 작업 영역에서 가장 중요한 동작에 사용 |
| 보조 버튼 | `CupertinoButton.tinted`. 다른 제안 등 보조 선택에 사용 |
| 텍스트 동작 | 기본 `CupertinoButton`. 편집 등 가벼운 동작에 사용 |
| 입력 필드 | `CupertinoTextField`와 항상 보이는 라벨·선택 여부·안내·오류 영역 |
| 콘텐츠 행 | 제목·종류·상태·관심 이유. 제목 최대 2줄, 관심 이유 최대 2줄, 전체 내용은 상세에서 확인 |
| 콘텐츠 이미지 | 정해진 영역 안에 표시. 이미지가 없을 때는 같은 크기의 종류 아이콘으로 대체 |
| 상태 배지 | `will consume` / `consumed`를 텍스트로 표시. 색만으로 구분하지 않음 |
| 필터 | `CupertinoSlidingSegmentedControl`로 하나의 필터를 선택. ‘전체’로 필터 해제 |
| 출처 영역 | 발견한 계기와 원문 링크를 보여줌 |
| 접근 동작 | 저장된 접근 방법에 따라 ‘글 열기’·‘듣기’ 등 실제 행동을 표시. 앱 내부 재생을 의미하지 않도록 함 |
| 추천 카드 | 콘텐츠 하나, 짧은 추천 이유, 접근 동작, 다른 제안. 원본 정보는 상세 화면과 동일한 표현 사용 |

새 화면은 이 컴포넌트를 우선 조합한다. 같은 역할의 컴포넌트를 기능별로 다시 만들지 않는다.

## 상태 표현

1. **비어 있음:** 무엇이 없는지와 가능한 다음 행동을 보여준다.
2. **처리 중:** 진행 상태를 보여주고 중복 실행을 막는다. 처리 실패 시 재시도할 수 있다.
3. **오류:** 원인과 복구 행동을 해당 작업 가까이에 표시한다. 입력한 내용은 유지한다.
4. **정보 없음:** 출처·이유·접근 링크가 없으면 내용을 추정하지 않는다. 필요한 경우 ‘추가하기’를 제공한다.
5. **AI 미지원:** 조건 기반 추천은 계속 제공하며, AI 기능의 사용 가능 여부는 사실대로 안내한다.
6. **긴 내용:** 목록은 요약하고 상세는 줄바꿈과 스크롤을 허용한다.

## Surprise me의 표현

재미는 선택 결과와 추천 이유에서 만든다. 일반 화면에도 과도한 장식을 반복하지 않는다.

1. 진입 동작은 주 강조색과 일관된 아이콘으로 눈에 띄게 한다.
2. 결과는 추천 카드로 보여주되 제목·상태·접근 동작은 공통 컴포넌트를 사용한다.
3. 결과가 나올 때 짧은 전환 효과를 허용한다. 반복 추첨에도 긴 연출을 강제하지 않는다.
4. 효과가 없어도 결과를 이해할 수 있어야 하며, 모션 감소 설정을 반영한다.

## Flutter 구현 기준

1. 색상·텍스트·기본 컴포넌트 스타일은 중앙 테마에서 관리한다.
2. 간격·모서리와 앱 전용 토큰도 한곳에 정의한다. 화면 파일에서 임의의 스타일 값을 추가하지 않는다.
3. 콘텐츠 행·상태 배지·추천 카드 등 앱 전용 컴포넌트는 공통 위젯으로 관리한다.
4. OS의 권한 요청·키보드·외부 링크 처리는 플랫폼 관례를 따르고, 앱 내부 콘텐츠 표현은 공통 기준을 유지한다.
5. 컴포넌트의 상태별 예시를 모은 갤러리를 만들어 기능 화면과 함께 유지한다.

## 기준 확정과 변경

첫 구현은 기능 화면보다 컴포넌트 갤러리를 기준으로 검토한다.

1. 버튼·입력·콘텐츠 행·상태 배지·추천 카드와 빈 상태·오류·처리 중 상태를 함께 표시한다.
2. 한국어 긴 제목, 출처 없는 항목, 이미지 없는 항목, 긴 감상 기록을 사용한다.
3. 글자 확대, 작은 화면, 라이트·다크 테마와 실제 iOS·Android 표시를 확인한다.
4. 토큰과 컴포넌트 규칙을 확정한 뒤 기능 화면에 적용한다.
5. 새 기능에 예외가 필요하면 공통 규칙 확장인지 화면 한정 배치인지 구분한다. 공통 변경은 기존 사용 화면에도 함께 반영한다.

현재 앱의 첫 화면은 기존 Flutter 카운터 템플릿이다. 제목·카운터·증가 기능과 카탈로그 진입을 유지하며, UI만 Cupertino로 전환했다. 카탈로그(`/catalog`)는 `features/catalog/`에서 토큰·컴포넌트·상태 예시를 독립적으로 관리한다. 카탈로그의 샘플 콘텐츠와 동작은 디자인 검토용이며, 앱의 사용 시나리오나 제품 화면을 확정한 것이 아니다.
